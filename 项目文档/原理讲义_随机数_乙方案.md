## 2. 为什么 2³² 不够：算一笔

### 2.1 你现在的发生器

`rng.py`：g = 1664525，c = 1013904223，M = 2³²。每调一次 `random()`，状态走一步：x ← (g·x + c) mod M，返回 x / M。

它的**周期**是多少？有一条定理（Knuth，Hull–Dobell 的 2 的幂特例）：M = 2ᵇ 时，**g ≡ 1 (mod 4) 且 c 是奇数** ⇔ 周期取满 = M。
- 1664525 ÷ 4 余 1 ✓，1013904223 是奇数 ✓ → 周期 = 2³² ≈ 4.29e9。

所以**旧发生器的质量没问题，是太短**：一共 4.29e9 个数排成一个圈，每个种子只是在圈上选一个起点。

### 2.2 两段撞上的概率（公式来历）

把整个序列想成一个周长 P 的圆。一次运行从起点开始，**顺时针连续用掉 L 个数**，占一段弧。两个种子 = 圆上两个**随机**起点。

两段弧有重叠 ⇔ 两个起点之间的距离（沿圆）< L（无论谁在前）。
固定第一个起点，第二个起点落在它前后各 L 的范围里才会撞 → 概率 ≈ **2L / P**（L ≪ P 时）。

30 个种子两两配对有 C(30,2) = 30 × 29 / 2 = **435 对**，期望撞上的对数 ≈ 435 × 2L / P。

**旧发生器，一步一步算：**

| 量 | 数 | 来历 |
|---|---|---|
| L | 约 2e7 | 10/28：2 万条历史 × 约 1000 个数 / 条 |
| P | 4.29e9 | 2³² |
| 一对撞上的概率 2L/P | 2 × 2e7 / 4.29e9 = **0.0093** | — |
| 期望撞上几对 | 435 × 0.0093 ≈ **4 对** | — |

实测查出 2 对明显的（2007 / 2025、2010 / 2019），和「约 4 对」同一个量级 —— 重叠**不是偶然倒霉，是必然**。

**新发生器（乙）：**

| 量 | 数 | 来历 |
|---|---|---|
| L | 1e5 × 152917 ≈ 1.53e10 | 10 万条，每条**预留** S 个（实际只用约 1000，这里按上限算） |
| P | 2⁶³ ≈ 9.22e18 | |
| 一对撞上的概率 | 2 × 1.53e10 / 9.22e18 ≈ **3.3e-9** | |
| 435 对期望 | ≈ **1.4e-6** | |

### 2.3 「每条历史跳到自己的起点」额外买到什么

旧做法：一个发生器从种子开始一直往下走，第 i 条历史用的数**取决于前面 i 条一共用了多少个**。

乙：第 i 条历史**永远**从 x₀ 往后第 i × S 个数开始。好处有三：

1. **可单独复现**：第 37 条历史出了怪事，可以只跑第 37 条，拿到一模一样的随机数（调试时用得上，判据也靠它，见 §7）。
2. **GPU 必须这样**：一个线程跑一条历史，线程之间**没有先后**，不能「接着上一条用」。每个线程自己用跳跃公式算起点，互不通信。
3. **和 MCNP / OpenMC 同一种做法**：MCNP 默认步长就是 152917；它的二进制是 100101010101010101（LANL 报告里说当初选它可能就因为这个花纹，没有更深的道理）。

代价：**一条历史用的数不能超过 S**，否则会用进下一条历史的段（只是相关，不是崩溃）。你的水模体一条历史约 1000 个数，离 152917 差 150 倍，安全；M5 三维、加 S(α,β) 以后要再看一眼（判据 4 盯这个）。

## 4. 跳跃公式：来历

### 4.1 走一步、两步、k 步

走一步：x₁ = g·x₀ + c
走两步：x₂ = g·x₁ + c = g(g·x₀ + c) + c = **g²·x₀ + (g + 1)·c**
走三步：x₃ = g·x₂ + c = **g³·x₀ + (g² + g + 1)·c**

规律：走 k 步 = **gᵏ·x₀ + (gᵏ⁻¹ + … + g + 1)·c**，全程 mod M。

也就是说：**走 k 步本身也是「乘一个数、加一个数」**，只是乘数变成 Aₖ = gᵏ、加数变成 Bₖ = c·(1 + g + … + gᵏ⁻¹)。OpenMC 手册把后面那个和写成 c·(gᵏ − 1)/(g − 1)（等比数列求和）。

⚠️ 但**不能照这个除法算**：g − 1 是偶数，在「mod 2⁶³」的世界里偶数没有倒数，除不了。所以下面换一条路：**不求和，只把映射拼起来。**

### 4.2 把两个映射拼起来

把「x → A·x + B」记成 **(A, B)**。先做 (A₁, B₁)，再做 (A₂, B₂)：

x → A₁x + B₁ → A₂(A₁x + B₁) + B₂ = **(A₂A₁)·x + (A₂B₁ + B₂)**

所以「先 1 后 2」拼成：**(A₂A₁, A₂B₁ + B₂)**。每一项都 mod M。

特例：一个映射和**自己**拼（走 k 步再走 k 步 = 走 2k 步）：(A, B) 拼 (A, B) = **(A², A·B + B)**。

### 4.3 为什么只要约 34 次：二进制

n 写成二进制，就是几个 2 的幂相加。例：n = 6 = 110₂ = 4 + 2。
- 准备「走 1 步」(g, c)，自己拼自己 → 「走 2 步」，再自己拼 → 「走 4 步」，再 → 「走 8 步」……（每次翻倍）
- n 的二进制哪一位是 1，就把那一档拼进「答案」里。

n 最大约 1e5 × 152917 ≈ 1.5e10 < 2³⁴，所以最多翻倍 34 次、拼 34 次。**直接走要 1.5e10 步**（Python 里光最后一条历史的起点就要走约 1 小时），跳只要几十次乘法。

**顺序会不会出错？** 这里所有档都是「同一个 (g, c) 走若干步」，「先走 2 步再走 4 步」和「先 4 后 2」都是走 6 步，结果一样（这批映射彼此可交换）。⚠️ **10/30 订正**：原来这里写「B 那一项写反了照样会错」，**错了**。这批映射都是同一个 (g, c) 的若干步，彼此可交换，所以 A₂B₁ + B₂ 和 A₁B₂ + B₁ **永远相等**（10/30 问答：先 ③ 后 ① 和先 ① 后 ③ 都是 (5, 7)）。顺序反了不会错；真会错的是**用错了哪一个 B**（如写成 A₂B₂ + B₁）、**漏乘 A**（B₁ + B₂）、**漏 mod** —— 判据 1 抓这些。

## 5. 一个一步一步的算例（小发生器，不用特殊值）

为了手算，换一个小发生器：**g = 5，c = 3，M = 16**，种子 **x₀ = 7**。（5 ÷ 4 余 1、3 是奇数 → 周期取满 16。）

**先一步步走（这是「另一条路」，用来对答案）：**

| k | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| xₖ | 7 | 6 | 1 | 8 | 11 | 10 | 5 | 12 | 15 |

（例：x₁ = (5×7 + 3) mod 16 = 38 mod 16 = 6；x₂ = (5×6 + 3) mod 16 = 33 mod 16 = 1。）

顺便看最低位：7、6、1、8、11、10、5、12 → 奇偶奇偶……交替，周期只有 2 —— 这就是 §3 说的「低位周期短」。

**再用跳跃，求 x₆（n = 6 = 4 + 2）：**

| 步 | 做什么 | 算式（都 mod 16） | 结果 |
|---|---|---|---|
| ① | 走 1 步 | (g, c) | (5, 3) |
| ② | 走 2 步 = ① 拼 ① | (5×5, 5×3 + 3) = (25, 18) | **(9, 2)** |
| 核 | 用 ② 算 x₂ | 9×7 + 2 = 65 → 65 mod 16 | 1 ✓（表里 x₂ = 1） |
| ③ | 走 4 步 = ② 拼 ② | (9×9, 9×2 + 2) = (81, 20) | **(1, 4)** |
| 核 | 用 ③ 算 x₄ | 1×7 + 4 | 11 ✓ |
| ④ | 走 6 步 = 先 ② 后 ③ | (A₃A₂, A₃B₂ + B₃) = (1×9, 1×2 + 4) | **(9, 6)** |
| 核 | 用 ④ 算 x₆ | 9×7 + 6 = 69 → 69 mod 16 | 5 ✓ |

明天你写的函数，就是让程序把上面这张表自动做一遍：一边把「档」翻倍，一边看 n 的当前最低位是不是 1。

## 6. ⚠️ 换了 M 以后，ξ 的区间变了（`lesson07_freegas.py` 第 525 行那条注释）

旧：x 最大是 2³² − 1，x / 2³² 最大 = 1 − 2⁻³²，在 double 里**能精确表示**，所以 ξ ∈ [0, 1)，`1 - rng.random()` 永远 > 0，`log` 安全。

新：x 最大是 2⁶³ − 1。double 只有 **53 位有效数字**，(2⁶³ − 1) / 2⁶³ = 0.99999999999999999989… 存不下，**四舍五入成 1.0**（我在容器里跑过：Python 打印 `1.0`）。大约最后 2⁹ = 512 个状态都会变成 1.0。

后果：ξ 可能**恰好等于 1.0** → `1 - ξ = 0` → `log(0)` → 程序炸。概率约 512 / 2⁶³ ≈ 5.6e-17 每次，一次 10 万条的运行约 1e8 次调用 → 约 5e-9，**调试时永远不出现**，就是第 525 行注释说的那种错。

两种处理（明天框架第 3 问你定）：

| | 做法 | 区间 | 代价 |
|---|---|---|---|
| 甲 | 只用 x 的**高 53 位**：x 右移 10 位（= 整除 1024），再除以 2⁵³ | [0, 1 − 2⁻⁵³]，**取不到 1** | 多一步移位；低 10 位扔掉（反正是周期短的那几位） |
| 乙 | 照旧 x / 2⁶³，接受偶尔得 1.0，在用 `1-ξ` 的地方另外防 | [0, 1] | 要找出所有 `log(1-ξ)`、`1/ξ` 之类的地方逐个防，漏一个就是埋雷 |

OpenMC 的 PCG 输出用的就是「高 53 位 × 2⁻⁵³」这一类做法。

## 9. 要用到的写法（规则 13：你用过的也过一遍）

| 写法 | 做什么 | 和项目无关的例子 | 你犯过 / 容易犯的错 |
|---|---|---|---|
| `a % b` | 取余 | 125 分钟 → `125 % 60` = 5（零头） | 用过，没犯过 |
| `a // b` | 整除（只要商） | `125 // 60` = 2（整小时） | 别写成 `/`：`/` 出来是 float，大整数会丢位 |
| `a >> k` | 右移 k 位 = 整除 2ᵏ | `200 >> 3` = 25（= 200 // 8） | 只对整数用 |
| `a & b` | 按位「与」；b = 2ᵏ − 1 时等于 `a % 2**k` | `13 & 1` = 1（13 = 1101₂，看最低位：奇数）；`12 & 1` = 0 | 和 `and` 不是一回事 |
| `2**63` | 2 的 63 次方 | `2**10` = 1024 | 🔴 **`2^63` 在 Python 里是「按位异或」，结果是 61，不报错** |
| 大整数 | Python 整数**不会溢出**，多大都精确 | `2**100` 照样精确 | 🔴 别写成 `2.806196910506780709e18`：那是 float，只有约 16 位有效数字，后面几位就错了，**乘数必须写整数字面量** |
| `while 条件:` | 条件为真就一直循环 | 数 1000 能被 2 连除几次：一直除到奇数为止 | 循环体里忘了改条件里的变量 → 死循环 |

**GPU 那一侧（了解）**：C / CUDA 的 64 位无符号整数（`uint64`）乘法超过 2⁶⁴ 会**自动截断** = 自动 mod 2⁶⁴；要 mod 2⁶³ 就再「与」一个 2⁶³ − 1。这正是大家都选 M = 2 的幂的原因：取模几乎不要钱。Python 里没有这种自动截断，**每一步都要自己 mod**，漏一次数就越长越大（不报错，只是变慢、结果不对）。
