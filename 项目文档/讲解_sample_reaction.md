## 0. 全文（照这个抄）

```python
def sample_reaction(sigma, total, xi,order):
    """按 sigma[k]/total 的占比抽一个反应道，返回原始下标 k。
    做法：按调用方传进来的 order（下标按 sigma 从大到小排好的队），
    从大的那头累加着扫。本函数不排序：order 由外面算好传入（9/18 定）。
    """
    assert len(order)==len(sigma),"order和sigma长度不一致"
    n = len(sigma)

    assert total > 0, "total 必须为正，实际是 %r" % total
    assert abs(sum(sigma) / total - 1) < 1e-12, \
        "sigma 与 total 对不上：sum(sigma)=%.17g  total=%.17g  比值=%.17g" \
        % (sum(sigma), total, sum(sigma) / total)
    assert 0 <= xi < 1, "xi 越界或是 nan: %r" % xi

    acc = 0.0
    for rank in range(n):
        k = order[rank]
        acc += sigma[k]
        if xi<acc/total:
            return k

    assert 1.0 - acc / total < 1e-12, \
        "扫完未返回，且缺口远大于浮点残差：xi=%.17g  acc=%.17g  total=%.17g  缺口=%.3g" \
        % (xi, acc, total, 1.0 - acc / total)
    for r in range(n - 1, -1, -1):
        if sigma[order[r]] > 0:
            return order[r]
    assert False, "sigma 全为零而 total>0，不可能：total=%.17g" % total


if __name__ == "__main__":
    sigma = [2.6, 0.0, 7.3, 0.45]
    total = sum(sigma)
    order = sorted(range(len(sigma)), key=lambda i: sigma[i], reverse=True)
    print("order =", order, "  total =", total)
    for xi in (0.37, 0.81, 0.97):
        k = sample_reaction(sigma, total, xi, order)
        print("xi = %.2f  ->  k = %d  (sigma[k] = %g)" % (xi, k, sigma[k]))
```

## 1. 它在干什么（一句话 + 一张图）

**一个核素有好几个反应道，每个道的截面是 `sigma[k]`。这次碰撞走哪个道？—— 走第 k 个道的概率是 `sigma[k] / total`。**

做法和你第 1 课的「累加抽道」、10/8 写的 `sample_E_table` 抽箱是**同一个东西**：把 [0, 1) 按各道的占比切成几段，看随机数 `xi` 落在哪一段。

用第 0 节那组数（4 个道，`sigma = [2.6, 0.0, 7.3, 0.45]`，`total = 10.35`）：

```
按原始顺序切（不排序）：
0 ──── 道0 ────┤道2 ────────────────────────────┤道3┤ 1
       0.2512                                0.9565

按 order = [2, 0, 3, 1] 切（大的在前，本函数的做法）：
0 ──────────── 道2 ──────────────┤── 道0 ──┤道3┤ 1
                              0.7053     0.9565
```

两种切法**每个道分到的长度一样**（道2 都是 0.7053），所以**分布一样**；但同一个 `xi` 落进的道可能不一样（逐点不一样）。
这就是 9/18 那条教训：和二分版对拍时，两版必须用**同一个顺序**切，否则不是在比同一个量。

**为什么要排序**：大的道放前面，大多数 `xi` 第一两圈就返回了。9/16 实测：软组织里平均读表 **1.1 次**，二分要 274.8 次。

## 2. 签名和四个参数（第 1–5 行，含文档字符串）

```python
def sample_reaction(sigma, total, xi,order):
```

| 参数 | 是什么 | 例子 | 谁负责 |
|---|---|---|---|
| `sigma` | 各道**微观**截面（barn）的列表，可以有 0（阈值以下的道） | `[2.6, 0.0, 7.3, 0.45]` | 调用方查表 |
| `total` | 总截面 | `10.35` | 调用方算好传进来（省一次求和） |
| `xi` | **一个**随机数，[0, 1) | `0.81` | 调用方抽（9/16 纪律：随机性由调用方负责，函数里没有 `rng`） |
| `order` | 下标按 `sigma` 从大到小排好的队 | `[2, 0, 3, 1]` | 调用方**整场只排一次** |

🔴 **传进来的是 `xi`（一个数），不是 `rng`（发生器）**。和 `sample_target(y, rng)` 不一样：那边函数里要抽好几个随机数，所以传发生器；这里只要一个，所以调用方抽好了传数。
你混过的一对：「发生器 `rng` vs 随机数 `rng.random()`」—— 这里传的是后者。

**返回**：**原始下标** `k`（第几个道），不是排名 `rank`。调用方拿它去 `nuclides[jn]["mts"][k]` 查是不是 MT=2。

**`order` 从哪来**（第 7 课 `lesson06_continuous.py` 第 182–187 行的做法）：

```python
order_H1 = sorted(range(len(sig)), key=lambda t: sig[t], reverse=True)
```

在**代表能量 0.0253 eV** 上按截面排一次，整场模拟不变。读法：「把 0, 1, 2, … 这些下标排序，排序的依据是 `sig[下标]`，大的在前」。
用第 0 节的数：`sorted([0,1,2,3], key=…, reverse=True)` → `[2, 0, 3, 1]`。
别的能量下排序不一定还是最优的 —— 但**只影响快慢，不影响对错**（任何顺序切出来，每个道的长度都一样）。

## 3. 入口的四条 assert（第 6–13 行；学的时候认真看，默写不写）

```python
    assert len(order)==len(sigma),"order和sigma长度不一致"
    n = len(sigma)
    assert total > 0, ...
    assert abs(sum(sigma) / total - 1) < 1e-12, ...
    assert 0 <= xi < 1, ...
```

| assert | 抓什么 |
|---|---|
| `len(order)==len(sigma)` | 传错了核素的 `order`（多核素时 `order[jn]` 的 `jn` 写错，这个最容易出）。长度不等时，扫描会漏道或越界 |
| `total > 0` | 后面要除以 `total`。0 → 除零；负数 → 物理上不可能 |
| `sum(sigma)/total` 和 1 差不到 1e-12 | 外面传进来的 `total` 和这组 `sigma` 不是一回事（比如传成了另一个能量的、或别的核素的总截面）。**这是「`total` 从外面传进来省一次求和」的代价**：省了求和，就得查一次它对不对 |
| `0 <= xi < 1` | `xi` 越界或是 `nan`。`nan` 和任何数比较都是 False，`0 <= nan` 不成立，所以这条也能挡 `nan` |

`%r`：按「程序员看的原样」打印，`nan` 会显示成 `nan`，字符串会带引号。`%.17g`：17 位有效数字，浮点数一位不丢。

`n = len(sigma)` 这一行夹在中间，是给下面 `range(n)` 用的。

## 4. 主体：排好序的线性扫描（第 15–20 行）—— 默写的核心

```python
    acc = 0.0
    for rank in range(n):
        k = order[rank]
        acc += sigma[k]
        if xi<acc/total:
            return k
```

| 名字 | 是什么 |
|---|---|
| `acc` | accumulate，**扫到目前为止加起来的截面**。在循环**外面**清零（纪律 6：它数的是「这一次调用里扫过的」，不是「每一圈」） |
| `rank` | **排名**：第 0 名、第 1 名…… |
| `k = order[rank]` | 第 `rank` 名是**原始的第几个道**。`rank` 和 `k` 是两样东西，别混 |
| `acc / total` | 前几名加起来占了 [0, 1) 的多少 |
| `xi < acc/total` | `xi` 落在「到这一名为止」的范围里 → 就是这一名，返回它的原始下标 |

**为什么是 `<` 不是 `<=`**（9/16 白板题⑦(3b)）：`random()` 返回 [0, 1)，左闭右开。每个道占一段**左闭右开**的区间 `[前面累计, 前面累计 + 自己)`。
`xi` 恰好等于某个分界点时，它属于**右边**那个道，所以用严格小于。

**零截面的道永远不会被返回**：排完序 0 全在末尾，前面的非零道加完 `acc/total` 已经是 1，而 `xi < 1`，一定在那之前就返回了。
（用第 0 节验：道1 的 σ = 0 排在最后；扫到道3 时 `acc/total = 1.0`，任何 `xi < 1` 都在这一圈或之前返回。）

**为什么写 `acc/total` 不写 `xi*total < acc`**：两种数学上等价。9/18 你选了前者，原文就是这样，抄原文。（第 13 课上 GPU 时，除法比乘法贵，到时候再看。）

## 6. 扫完了还没返回（第 22–28 行）—— 学的时候看懂，默写时只写两行 `for` + `if` + `return`

```python
    assert 1.0 - acc / total < 1e-12, ...
    for r in range(n - 1, -1, -1):
        if sigma[order[r]] > 0:
            return order[r]
    assert False, "sigma 全为零而 total>0，不可能：total=%.17g" % total
```

**什么时候会走到这里**：`acc` 是按 `order` 的顺序加出来的，`total` 是调用方按原顺序加出来的。浮点数加法**换个顺序结果可能差最后一位**，于是 `acc/total` 可能是 0.9999999999999998 而不是 1。如果 `xi` 恰好落进这条缝，扫完一圈都没返回。
9/18 实测：随机扫 39.9 万组，8.8 万组有这条缝，最宽 3.33e-16。
⚠️ 本项目的 LCG 最大只能吐出约 `1 − 2.3e-10`，够不到这么窄的缝，所以**现在这条路走不到**。换成 numpy 的 64 位发生器就走得到。「它现在不响」和「它是坏的」是两回事。

逐行：
1. **assert**：抓「扫完没返回，而缺口大得不像浮点残差」—— 那就不是舍入，是真的 bug。
2. **`range(n - 1, -1, -1)`**：🆕 三个参数的 `range(起点, 终点, 步长)`，**倒着数**：`n-1, n-2, …, 0`（终点 −1 不含）。`n = 4` 时是 `3, 2, 1, 0`。
3. 从**最后一名往前**找第一个截面 > 0 的道，返回它。理由：缝在 [0, 1) 的最右端，按「排好序的切法」，最右端属于**最后一个非零道**。（直接返回 `order[n-1]` 不行，那可能是零截面道。）
4. **`assert False`**：前面 `total > 0` 已经保证至少有一个非零道，所以这一行正常不可能走到；走到了说明 `sigma` 和 `total` 根本对不上。
   **为什么还要写**：不写的话，函数走到底会默默 `return None`，调用方拿 `None` 当下标，报错的地方离真正的错很远（9/9 白板题⑤「打印出一片 None」）。
