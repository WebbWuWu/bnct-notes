## 零、对现有代码的诚实评估

现有 `E:\BNCT_GPU\Phase_1\` 约 25 万字符的 C++，全部由 AI 生成。逐项看：

**做得对的部分（值得保留作参考）**
- 自洽性诊断（自由程均值、⟨μ_lab⟩、H 散射占比、权重账）是**真正的验证方法**，这套思路要学会并且自己重做一遍。
- 隐式俘获 + 俄罗斯轮盘赌的权重管理逻辑是对的。
- CM→LAB 散射运动学是对的。

**致命问题**
1. **一行 CUDA 都没有。** 项目叫 GPU 加速，`Phase_1` 全是 CPU C++。所谓 "523k / 1.19M hist/s" 是 CPU 单线程数字，跟 GPU 无关。面试老师第一句问"你的 GPU 加速在哪"，现在答不上来。
2. **单能 0.0253 eV 热中子束不是 BNCT。** BNCT 临床用的是超热中子束（1 eV – 10 keV），靠中子在组织里慢化到热能再被 ¹⁰B(n,α)⁷Li 俘获。跳过慢化过程 = 跳过 BNCT 最核心的物理。现在这个程序本质是"水中热中子扩散演示"。
3. **工程结构崩坏。** `physics_engine.h` 一个 37 KB 头文件里塞进了手写的 ZIP 解压器和 NPY 解析器。没有 Makefile/CMake，没有 git，没有单元测试框架，全 header-only。这是 AI 生成代码的典型形态，人类维护不了。
4. **全用 double。** 消费级 GPU 的 FP64 吞吐通常是 FP32 的 1/32 – 1/64，直接移植会慢到没有意义。
5. 深度剂量表里 MC/扩散比值一路掉到 0.0001，报告自己也承认"最大偏差 100%"——这不是通过验证，是没有可信参考解。

**结论：不要在这堆代码上继续加功能。** 把它降级为参考资料，自己从零重写一个小得多、但每一行都能讲清的程序。理由很硬：面试要当场写代码，只有自己写过的才守得住。

## 一、总体策略：Python → C++ → CUDA

为什么不直接上 C++/CUDA：
- 零基础直接写 C++，第一周会全部消耗在编译错误和段错误上，看不到任何物理，士气崩掉。
- 更重要的：**GPU 程序必须有一个可信的参考实现来对拍。** 没有金标准，你永远不知道 GPU 版算错了没有。这个金标准就是你自己写的 Python 版。

三层结构，每一层都完整可运行、都有验证：

| 层 | 语言 | 作用 | 面试价值 |
|---|---|---|---|
| L1 | Python | 物理正确的参考实现，慢但对 | 讲清物理和抽样方法 |
| L2 | C++ | 同样物理，单线程，逐位对拍 L1 | 讲清数据结构与性能 |
| L3 | CUDA | GPU 并行，对拍 L2 | 讲清并行策略与加速比 |

## 二、16 周日程

### 阶段 A（第 1–2 周）Python 语法 + 第一个蒙特卡洛
学的语法严格限定在"写 MC 需要的那 20%"：变量、`if`、`for`/`while`、函数、列表、numpy 数组、读写文件、画图。不学类、装饰器、生成器。

产出：**1D 平板单能中子穿透程序**，与解析解 exp(−Σt·x) 对拍到 3 位有效数字。

关键子任务（每个都是面试白板题）：
1. 手写线性同余发生器 LCG，检验均匀性
2. 逆变换抽样指数分布，验证 ⟨s⟩ = 1/Σt
3. 各向同性方向抽样（注意 μ 均匀而不是 θ 均匀）
4. 碰撞后判定吸收/散射（用累积概率）
5. tally（打分器）+ 相对误差 + FOM

### 阶段 B（第 3–4 周）Python 版物理补全
产出：**3D 水模体 + 连续能量 + 多核素**的 Python MC。

1. 从 `lib80x_hdf5` 读 ENDF/B-VIII.0 截面（H1、O16、C12、N14、B10），做对数-对数插值
2. 元素混合 → 宏观截面 Σ(E) = Σᵢ Nᵢ σᵢ(E)
3. 弹性散射 CM 系运动学：E' = E·[(A²+2Aμ_cm+1)/(A+1)²]
4. free-gas 热运动模型（低能必须有，否则中子无法热化到 0.025 eV）
5. ¹⁰B(n,α)⁷Li 反应：2.31 MeV 与 2.79 MeV 两分支，α 和 ⁷Li 就地沉积
6. BNCT 四分量剂量：D_boron、D_nitrogen(¹⁴N(n,p)¹⁴C)、D_hydrogen(快中子反冲)、D_gamma(²H 俘获 2.224 MeV)
7. **验证：用 OpenMC 跑同样问题，两条深度剂量曲线在 1σ 内重合**

这一步做完，你已经有一个真正的 BNCT 剂量计算器了，只是很慢。

### 阶段 C（第 5–7 周）C++ 重写
学的语法同样限定：类型、指针/引用、`struct`、`std::vector`、函数、头文件与源文件分离、`g++` 编译、`gdb` 调试、CMake、git。

产出：**C++ 版**，同一输入下每个 tally 与 Python 版在统计误差内一致。

工程规范（面试老师看的就是这个）：
- `src/` `include/` `tests/` `data/` 分离，每个 `.h` 只做一件事
- CMakeLists.txt
- git 提交，每个 commit 一个功能
- 单元测试：抽样分布的卡方检验、能量守恒、权重守恒

### 阶段 D（第 8–10 周）CUDA 移植
1. CUDA 基本概念：thread / block / grid、`__global__` / `__device__`、显存分配拷贝
2. 并行策略：**一个 thread = 一条中子历史**（history-based）。先做这个，简单且够用。
3. cuRAND：每个 thread 独立种子，`curand_init(seed, tid, 0, &state)`
4. 打分用 `atomicAdd`，先跑通再谈优化
5. **float vs double**：物理量算 float，累加器算 double（或用 Kahan 求和）
6. 优化三板斧，每一步都测加速比：
   - 减少 warp divergence（把不同能量的中子分箱）
   - 截面数据放 texture memory / `__ldg`
   - event-based 重排（进阶，做不完不做）

产出：**加速比曲线 + roofline 分析**。这是面试最亮的一页 PPT。

### 阶段 E（第 11–13 周）真实 BNCT 场景
1. 超热中子源谱（读一个真实束流谱，比如 京都大学 KUR 或 Tsing Hua THOR 公开谱）
2. CT 体素模体（可用公开头部体模，或 ICRP 参考体模）
3. Woodcock（delta-tracking）跨体素追踪
4. ¹⁰B 浓度分布（BPA 药物分布模型，肿瘤/正常组织比 3.5:1）
5. 输出 DVH（剂量体积直方图）

### 阶段 F（第 14–16 周）验证、成文、面试训练
1. 与 OpenMC / PHITS 全面对标，做偏差表
2. 性能表：CPU 单线程 / CPU 多线程 / GPU，历史数-时间曲线
3. 写技术文档 + 答辩 PPT
4. **每天 30 分钟手写代码训练**（见下）

## 三、面试"当场写程序"专项训练

从第 1 周开始，**每天纸上手写一道**，不看 IDE、不看补全。这些题就是你程序的原子：

**基础层**
1. 线性同余发生器
2. 逆变换法抽样指数分布
3. 抽样各向同性方向 (μ, φ) → (u, v, w)
4. 舍选法（rejection sampling）抽样任意 pdf
5. 数组二分查找（截面查表的核心）
6. 线性插值 / 对数插值

**MC 层**
7. 用 MC 估计 π，并给出误差随 N 的收敛率
8. 1D 平板穿透概率，与 exp(−Σt·d) 比较
9. 从离散分布抽样（用累积概率 + 二分）
10. 计算样本方差与相对误差（注意用 per-history 累加，不是 per-event）
11. 隐式俘获的权重更新公式
12. 俄罗斯轮盘赌，证明它无偏

**物理层**
13. CM→LAB 弹性散射能量与角度关系
14. 给定 Σs、Σa，求扩散长度 L
15. 光线-长方体求交（voxel traversal 的 slab method）

**C++/CUDA 层**
16. 手写 `std::vector` 的简化版（构造/析构/push_back）
17. 写一个 CUDA kernel 做向量加法
18. 解释 `atomicAdd` 为什么必要，以及它的性能代价
19. 解释 warp divergence，举一个 MC 程序里的例子

老师大概率会问的是 1–10 里的几道，再加一道"你程序里最难的一个 bug 是什么，怎么定位的"。**这最后一题必须提前准备真实答案**——所以调试过程要写日志。

## 四、纪律（决定成败）

1. **禁止让 AI 直接给完整代码。** 可以问概念、问 bug、问"我这样写对不对"，但每一行必须自己敲。
2. **每天写调试日志**：今天卡在哪、怎么定位、根因是什么。这是面试素材，也是唯一让能力沉淀的方式。
3. **git 从第一天开始用**，每天至少一次 commit。
4. **每一个新功能上线前先写验证。** 没有验证的功能等于没做——这正是现有 AI 代码的教训。
5. **每周日回看一次这个路线图**，标记完成项，调整下周。
