### 🔴 当天最值钱的一课：验证 1 只 print，不 assert

白板题⑤ 重写版跑出来：

```
e=0.5     -> k=None      ←
e=1.0     -> k=None      ←
e=3.0     -> k=2
...
验证 2: 不一致 0 次
验证 3: 最坏读表 53 次
三条全过。               ← 它说"全过"
```

**函数在两个边界分支上只赋值 `lo=hi=...` 没有 `return`，Python 走到函数底默认返回 `None`。**

> 🔴 **判据盲区第八个标本，也是最贵的一个：一条判据如果不判定，它就不是判据，是一行日志。**
> **对策已落地**：把六个期望值写成 `expect = {...}` 字典，循环里 `assert k == expect[e]`。**判定交给程序，不交给眼睛。**
> （**9/15 第二次应用**：肉眼读斜率 −88.5，程序算 −0.499776。）

### 恒真 assert，第五次

用户把 `assert steps < 100` 抄进去了，但**没有 `steps = 0` 和 `steps += 1`**。

> **只补 `steps = 0` 而漏掉 `steps += 1` 的话，程序正常跑、四条验证全过，而 `assert 0 < 100` 永远为真 —— 一根断了的保险丝。**
> **前四次恒真 assert 都被抓出来了，这次不会 —— 因为代码本来就是对的，没人会发现保险丝断了。**
> **新动作：写完防死循环的 assert，故意制造一次死循环，确认它真的会响。没见过它响，不算装上了。**

### 判据说假话的三种形态（当天集齐；9/15 补上第四种）

| 形态 | 例子 |
|---|---|
| **判据没响** | `math.pi2` 误改；验证 1 打印 None |
| **判据响了，但指向错误的原因** | `find` 遇到 NaN 时报「二分没有收敛」，真因是输入是 NaN |
| **判据响了，但它自己在报错路上先炸** | `assert s(e1)==S[k], "...%.6f" % S(e1)` —— 大写 `S` 是数组，失败时看到的是 `TypeError` |

> **第三种最阴**：Python 只在 assert **失败时**才计算消息，所以判据通过时这个坑完全隐形。
> **纪律：assert 的消息必须至少手动触发一次，看它长什么样。**
