## 0. 要做成什么（一句话）

把库里 **H1、O16、B10 三个核素的弹性散射角分布换成「质心系各向同性」**，另存成一份小截面库；OpenMC 改用这份库，**其余（材料、几何、源、tally、粒子数）和 `lesson11_openmc.py` 一模一样**，重跑水模体。

为什么三个都改，不只改 O16：10/19 你定的乙原方案就是「把材料里每个核素的弹性都改掉」。你的程序**对每个核素**都按质心系各向同性处理（近似 #4），三个都改以后，OpenMC 和你的程序在这一点上**做法完全相同**，两边**只剩其他近似不同**。这样才算「只差一个变量」。B10 只有 15 ppm，改不改都看不出来，但改了才和你的程序完全一致。

### 只动了什么、没动什么（面试会问）

| | 改了吗 | 为什么 |
|---|---|---|
| 弹性散射**出射角**（质心系 μ 的分布） | ✅ 改成在 [−1, 1] 上均匀 | 这就是近似 #4 |
| 弹性截面 σ_el(E)、所有其他截面 | ❌ | 判据 ③ 逐位核对 |
| **MT=301 加热系数** H(E) | ❌ | 库里的 H(E) 是 NJOY 按**真实**角分布算好的一列数；你的程序也直接查这一列。所以两边每段路程乘的系数相同，只有「中子飞到哪里」不同 |

最后一行要能说清楚：**方案乙只改输运，不改记账。** 10/23 你自己比过 O16 在 1 MeV 处的 H(E)：库值 8.983e5，按各向同性估算 8.997e5，**只差 0.16%**。说明近似 #4 在 1 MeV 处对「一次碰撞丢多少能量」影响很小。方案乙看的是另一件事：**角度改了以后，中子在空间上走到哪里**，以及能谱里更高能的那一段。

## 2. 新用法（6 个）

例子用 Fe56 / Cu63，库里都有，可以在 WSL 里先跑一遍看看输出。

### 2.1 把一个核素的整份数据读成 Python 对象

```python
fe = openmc.data.IncidentNeutron.from_hdf5("/mnt/e/BNCT_GPU/lib80x_hdf5/Fe56.h5")
print(fe.name)                    # 'Fe56'
print(fe.temperatures)            # ['250K', '294K', '600K', ...]
cap = fe.reactions[102]           # .reactions 是字典：键 = MT 号，值 = 这个反应
print(cap.xs["294K"](0.0253))     # 0.0253 eV、294 K 的 (n,γ) 截面，单位 b（圆括号：它是个能调用的函数）
```

和你学过的 h5py 写法对照：你的 `load_nuclide` 是自己一层层 `f[name]["reactions"]["reaction_102"]` 往下拿数组；`from_hdf5` 是 OpenMC 帮你**一次把整份文件读成对象**，以后用 `.reactions[102]` 这种属性和字典的写法往下取。

### 2.2 从「弹性反应」一路拿到角分布

```python
el = fe.reactions[2]                  # MT=2 弹性
print(el.center_of_mass)              # True：下面的 μ 是「质心系」里的散射角余弦
d = el.products[0].distribution[0]    # products[0] = 出射的那个中子；distribution[0] = 它唯一的一段分布
ang = d.angle                         # 角分布对象
print(len(ang.energy))                # 入射能量格点个数
print(ang.energy[0], ang.energy[-1])  # 最低、最高的入射能量（eV）
print(ang.mu[-1].mean())              # 最高能那一点上 μ 的平均值 μ̄_cm
```

结构和你的 `XS[道][格点]` 很像：`ang.energy` 是一列入射能量，`ang.mu` 是**同样长**的一个列表，`ang.mu[i]` 就是「入射能量 = `ang.energy[i]` 时，μ 怎么分布」。两个格点之间的能量，OpenMC 自己插值。

`.products[0].distribution[0]` 这两个 `[0]` 是列表下标，不是 MT 号。弹性只有一个出射粒子、一段分布，所以都是 `[0]`。

### 2.3 「在区间上均匀」的分布，和用它搭一个新的角分布

```python
g = openmc.stats.Uniform(0.2, 0.9)          # 在 [0.2, 0.9] 上均匀；g.a = 0.2，g.b = 0.9
two = openmc.data.AngleDistribution(
    [5e3, 3e6],                              # 第一个参数：入射能量列表（eV）
    [openmc.stats.Uniform(0.2, 0.9),         # 第二个参数：同样长的列表，每个能量一个分布
     openmc.stats.Uniform(0.2, 0.9)])
```

- 两个格点上都是同一个均匀分布，中间插值出来还是它。所以**两个格点就能表示「所有能量都一样」**。
- 导出时 OpenMC 会自动把 `Uniform` 换成两点的表格（源码 `to_hdf5` 第 74–75 行），不用你自己转。
- 这个例子的区间是随手取的，**不是**你要的区间。你要的区间想一想：μ 是余弦，「各向同性」意味着什么？

### 2.4 把新角分布装回去

```python
d.angle = two          # 用新对象「换掉」旧的（不是改旧对象里的数）
```

🔴 **你的高频错**：属性名拼错不报错，会悄悄新建一个属性（10/11 `self.satet`、10/23 `g_B_sq`）。这里写成 `d.angel` 也一样不报错，库里的角分布原封不动。判据 ① 专门抓这个。

### 2.5 把改过的对象存成新的 `.h5`

```python
fe.export_to_hdf5(os.path.join(某文件夹, "Fe56_copy.h5"), mode="w")
```

- `mode="w"`：文件已经存在就清空重写，和 `open(…, "w")` 一样。**默认是 `"a"`（追加）**：第二次跑的时候文件里已经有 `Fe56` 这个组，会直接报错。
- 存出来的文件里核素名还是 `Fe56`（名字来自对象，不来自文件名），所以材料里写 `'Fe56'` 就能找到它。
- `某文件夹` 是占位，别照抄（10/13 `'/home/abc/run1/'` 的教训）。

### 2.6 自己生成一份截面库清单（`cross_sections.xml`）

```python
lib = openmc.data.DataLibrary()             # 空清单
lib.register_file(路径甲)                    # 登记一个 .h5（它自己读出里面是哪个核素）
lib.register_file(路径乙)
lib.export_to_xml(os.path.join(某文件夹, "my_xs.xml"))
```

- 清单里**只有你登记的那几个文件**。材料里出现了清单里没有的核素，OpenMC 一开跑就报 `Could not find nuclide …`。水模体只有 H1、O16、B10，三个都登记就够了。
- 切换到新清单：`openmc.config["cross_sections"] = 新 xml 的路径`。这一行之后调用的 `run()`，OpenMC 就读新清单（它是通过环境变量传给 OpenMC 程序的）。**写在所有 import 之后**（见第 1 节）。
