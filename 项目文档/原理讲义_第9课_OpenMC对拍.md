## 0. 一句话

**拿一个世界上很多人用、验证过的程序（OpenMC），把你算过的问题原样再算一遍。两边对上，你的程序就有了「外部的独立证据」。**
到现在为止你所有的判据都是「你的程序 vs 纸上公式」或「你的程序的两种模式互相比」。第 9 课是第一次「你的程序 vs 别人的程序」。

面试时这句话的分量：「我写的 GPU 蒙卡程序，和 OpenMC 在 BNCT 深度剂量上逐层一致，偏差表在这里」—— 比任何一条内部判据都硬。

## 1. 🔴 先纠正里程碑 1 的写法：「1σ 内重合」不能照字面理解

《学习路线图》和 v4 写的是「两条深度剂量曲线在 1σ 内重合」。**如果按字面要求 30 层每一层都在 1σ 内，那两个完全正确的程序也几乎不可能做到。**

**来历**：两边都对的时候，每层的偏离 `z = (A − B) / sqrt(SE_A² + SE_B²)` 近似服从标准正态分布。标准正态落在 ±1 之内的概率是 **68.3%**。30 层独立的话，全部落在 ±1 内的概率是 0.683³⁰ ≈ **1e-5**。

**算例**（真实发生过的）：今天上午判据 2 复查，同一份正确代码、两个种子，第 1 层就出现了 +2.33 SE。

**所以里程碑 1 的判据要改成统计上正确的说法**（第 9 课框架第一轮定）：

| 方案 | 怎么判 | 代价 |
|---|---|---|
| **甲** 比例 | 约 68% 的层在 1σ 内、约 95% 在 2σ 内、没有一层超过 4σ | 直观，面试好讲；但「约」要给范围（30 层时 1σ 内的层数在 15–25 之间都正常） |
| **乙** χ² | 30 层的 z² 加起来 ≈ 30（自由度），落在 χ²₃₀ 的 99% 区间 [13.79, 53.67] 内（95% 区间是 [16.79, 46.98]） | 一个数说清楚；但相邻层相关（第 9 课 §8 讲），χ² 会偏大一点 |
| **丙** 甲 + 乙都报 | 偏差表里两个都写 | 最完整 |

> 这不是降低标准，是把标准**说对**。「每层都在 1σ 内」反而说明误差棒被估大了（或者两边共用了随机数）。

## 2. 记号

| 记号 | 含义 |
|---|---|
| **OpenMC** | MIT 开发的开源蒙卡输运程序（C++ 内核 + Python 接口）。你的 conda 环境名就叫 `openmc`，应该已经装好 ⚠️（开工先 `import openmc; print(openmc.__version__)`） |
| **批（batch）** | OpenMC 把 N 个粒子分成若干批跑，用**批间的离散**估计误差棒 —— 和你今天判据 4a 的做法一样 |
| **tally** | OpenMC 里的「打分」。一个 tally = 在哪里打（filter）+ 打什么（score） |
| **filter** | 打分的「分箱」：按网格（mesh）、按栅元（cell）、按能量、按核素…… |
| **score** | 打的量：`flux`（径迹长度）、`(n,gamma)`（反应率）、`heating`（加热）…… |
| **每源粒子（per source particle）** | OpenMC 所有 tally 的默认归一化，和你的「÷N」是同一件事 |
| **S(α,β)** | 热散射律：氢在水分子里被化学键束缚时的散射数据（文件 `c_H_in_H2O.h5`）。**你的程序没有它**（自由气体，近似 #9） |
| **mean ± std. dev.** | OpenMC 输出里的 `std. dev.` 是**均值的标准误 SE**，不是单条历史的 σ₁ ⚠️（这对名字你混过） |

## 3. 🔴 对拍最重要的一件事：两边必须是「同一个问题」

**对不上的时候，99% 不是谁的程序错了，而是两边算的根本不是同一个问题。**（第 7 课「悬着的 1%」就是这个教训：两边比的不是同一个量。）

所以开工前先把下面这张**对齐清单**逐格对上，和交接文档第四节「逐位相同的前提清单（八格）」是同一个思路：

| # | 项 | 你的程序 | OpenMC 要怎么设 | 对不上会差多少 |
|---|---|---|---|---|
| 1 | **截面库** | `lib80x_hdf5`（LANL 版 ENDF/B-VIII.0） | **同一个库**：`openmc.config['cross_sections']` 指向 `E:\BNCT_GPU\lib80x_hdf5\cross_sections.xml` | 换库能差几个百分点。**同一个库 = 这一格自动对上**（你这个库本来就是给 OpenMC 用的格式） |
| 2 | **温度** | 294K 那一张表 | 材料温度 294 K，温度方法取「最近」 ⚠️ | 热区截面差 ~1%（1/v 部分随温度变） |
| 3 | **材料** | H 0.102 / C 0.143 / N 0.034 / O 0.708 + ¹⁰B 15 ppm，质量份额，ρ = 1.06 | `add_nuclide(名字, 份额, 'wo')`（`wo` = weight fraction，质量份额）× 5 个；`set_density('g/cm3', 1.06)` | 份额写成原子份额（`'ao'`）会差很多 —— 氢的原子份额约 0.63 |
| 4 | 🔴 **热散射** | **没有 S(α,β)**，自由气体 | **不要调 `add_s_alpha_beta`** | 加了的话热区通量形状会变，D_B 峰差几个百分点 —— 那是「物理差别」，不是 bug。先不加对拍；**对完再加一次，量出近似 #9 的大小**（这是面试材料） |
| 5 | **自由气体的适用范围** | 所有能量都用自由气体抽靶核 | OpenMC 默认只在 `E < 400 kT` 用自由气体，以上当靶核静止 ⚠️ | 400 kT ≈ 10 eV 以上靶核热运动可忽略（`y` 很大时你的舍选法也退化成静止靶），**应该对得上** |
| 6 | **源能谱** | KUR 三群 → 10 箱，**箱内 ln E 均匀** | 见 §5 —— 有坑 | 箱内分布不同 → 源谱不同 → 全部曲线都差 |
| 7 | **源位置 / 方向** | `z = 0`，`(0, 0, 1)` 垂直入射 | 点源放在 `z` 稍大于 0（比如 1e-6 cm）⚠️，单向 `(0, 0, 1)` | 源正好在边界面上，OpenMC 可能找不到所在栅元 |
| 8 | **几何** | 一维无限大平板，d = 15 cm | 两个 z 平面（真空边界）+ 四个 x、y 平面（**反射边界**） | x、y 用真空边界会侧漏，深处偏低 |
| 9 | **光子** | 不输运光子 | `photon_transport = False`（默认） | 打开的话 heating 会多出光子沉积 |
| 10 | **已知近似**（你有、OpenMC 没有） | 非弹当吸收（近似 #7）；N-14 (n,α)、B-10 (n,p)/(n,t) 不进打分 | OpenMC 都按真实物理算 | 源 ≤ 2 MeV 时只有 B-10 非弹开着，硼密度极低 → 预期 < 0.1%；D_N 少掉的那部分只有快中子能触发 → 预期很小。**都要在偏差表里列出来** |

## 4. OpenMC 模型怎么搭（Python 接口，一共四块）

OpenMC 的输入就是一个 Python 脚本，造四样东西，导出成 XML，然后 `openmc.run()`：

```
① materials   材料：一种「软组织 + 15 ppm 硼」
② geometry    几何：一个盒子，z 方向 0–15 cm，x、y 方向反射
③ settings    设置：固定源模式、粒子数、批数、源
④ tallies     打分：30 层网格 × 若干 score
```

下面只写「每块要做什么」和用到的 API 名字，**代码你写**（第 9 课框架第一轮再细问）。

### 4.1 材料

```
新建 Material → 逐个 add_nuclide（5 个，'wo'）→ set_density → temperature = 294
→ 放进 Materials 集合 → export_to_xml
```
🔴 不要 `add_element('H', …)`：element 会按天然丰度拆成 H1 + H2，你的程序只有 H1。用 `add_nuclide`。

### 4.2 几何

```
6 个平面：z=0、z=15（boundary_type='vacuum'），x=±L、y=±L（boundary_type='reflective'）
→ 一个 Cell，区域 = 这 6 个面围起来的盒子，填你的材料
→ Universe → Geometry → export_to_xml
```
`L` 取多少无所谓（反射边界下横向是无限的），取个非特殊值比如 7.3 cm。

### 4.3 设置

```
Settings：run_mode = 'fixed source'；particles = 每批粒子数；batches = 批数
源：位置 Point((0, 0, 1e-6))，方向 Monodirectional((0, 0, 1))，能量见 §5
（可选）survival_biasing = True —— 就是你的隐式俘获 + 轮盘赌
```

### 4.4 打分

```
RegularMesh：dimension = [1, 1, 30]，lower_left = (−L, −L, 0)，upper_right = (L, L, 15)
→ MeshFilter
→ 几个 Tally（§6 细讲 score 和核素）
```

**跑起来以后**：结果在 `statepoint.<批数>.h5` 里，用 `openmc.StatePoint` 读，`get_tally(...).mean` / `.std_dev` 拿到数组。

## 5. 🔴 源能谱在 OpenMC 里怎么写 —— 第一个坑

你的抽样：**先按份额抽箱，箱内 ln E 均匀**（即箱内 p(E) ∝ 1/E）。

OpenMC 的能量分布有 `Discrete`、`Uniform`、`Tabular`、`Maxwell`、`Watt`、`Mixture`……
**没有一个直接叫「分箱 1/E」。**最接近的是 `Tabular(x, p, interpolation='histogram')` —— 但 histogram 的意思是**箱内 E 均匀**（p(E) 在箱内是常数），不是 ln E 均匀。

**算例：差多少？**超热段最宽的箱 [1000, 3000] eV：
```
箱内 ln E 均匀（你的）：  E < 2000 eV 的占比 = ln(2000/1000) / ln(3000/1000) = 0.693 / 1.099 = 0.631
箱内 E 均匀（histogram）：E < 2000 eV 的占比 = (2000 − 1000) / (3000 − 1000)  = 0.500
```
差了 13 个百分点。快群 [1e4, 2e6] 更夸张：你的抽样里 < 100 keV 占 43.5%，histogram 下只有 4.5%。**快群一变，D_H 会差很多。**

**三个方案，第 9 课框架第一轮定：**

| 方案 | 做法 | 代价 |
|---|---|---|
| **甲** 细分箱 | 每个箱再切成 M 个对数等宽的子箱，子箱份额按 1/E 分（就是你的 `table_1overE`），交给 `Tabular(…, 'histogram')` | 子箱内仍是 E 均匀，但 M 大了误差就小：M = 50 时子箱宽度比 (2e6/1e4)^(1/50) = 1.11，箱内近似误差 < 1% ⚠️（要算一下）。**最稳** |
| **乙** 每箱一个分布再混合 | `Mixture([各箱分布], [份额])`，每个箱用一个 1/E 形的分布 | 精确；但要找到 OpenMC 里能精确表示「箱内 1/E」的分布类型 ⚠️（`PowerLaw` 指数取 −1 时公式里有 1/(n+1)，大概率不支持） |
| **丙** 两边都换成 histogram | 你的程序也改成箱内 E 均匀 | 改的是**你的**源，等于为了迁就 OpenMC 改物理；而且第 8 课交付图就作废了。**不推荐** |

🔴 不管选哪个，**OpenMC 那边的源也要做一次源抽样判据**：从 OpenMC 的源里直接抽 10 万个能量（`openmc.lib` 或者开一个只记源能量的 tally ⚠️），和你的 5b 用**同样的五项**比。**源对不上，后面一切对比都没意义。**

## 6. 打分：OpenMC 的 tally 怎么对应你的四个量

| 你的量 | 你的单位 | OpenMC 怎么打 | 换算成同一个单位 |
|---|---|---|---|
| 通量 `track_sum/N` | cm（每源中子在这层的径迹长度） | score `flux`，网格 filter | OpenMC 的 `flux` 也是「径迹长度 / 源粒子」，**单位 cm** ⚠️ → 直接比 |
| D_B（`Br`） | eV/源中子 | score `(n,a)`，核素只选 B10 → 反应次数/源粒子 | × Q_avg = 2.341569e6 eV（硼常数，和你的 `Bc` 比最干净；逐道 vs 常数只差 2.6e-7） |
| D_N（`Nc`） | eV/源中子 | score `(n,p)`，核素只选 N14 → 反应次数/源粒子 | × Q_600 = 625876.1 eV。⚠️ `(n,p)` 是 MT=103 = 600–649 之和，≤ 2 MeV 时只有 600 开着 |
| (n,γ)（`ag`） | 反应次数/源中子 | score `(n,gamma)`，全部核素 | 直接比 |
| D_H（`DH`） | eV/源中子 | 🔴 **没有直接对应的 score**，见 §7 | — |

**归一化**：两边都是「每源粒子」，而且网格的横向面积 A 在两边都**根本没出现**（你的程序是一维；OpenMC 的 tally 是整层积分）。所以层对层直接比，Gy·cm² 用同一个 `to_gy` 系数换。
⚠️ 唯一要小心的：OpenMC 网格 tally 的 `flux` 是**整个网格单元里的径迹长度之和**，不是除过体积的。你的 `track_sum/N` 也是「这层里的径迹长度」，**应该一致**。开工第一件事就是在单能、纯吸收的假问题上验这一条（和你的判据 3a 同一个闭式）。

## 7. 🔴 D_H 在 OpenMC 里怎么对 —— 第二个坑

你的 D_H = 每次散射 `wt × (E − E')`，**只算弹性反冲**，热区上散射记负值。

OpenMC 能打的最接近的量是 score `heating`：每个核素的 **KERMA**（库里的 MT=301，NJOY 的 HEATR 模块预先算好的「每次碰撞平均留下多少能量」）。但它和你的 D_H **不是同一个量**：

| 差别 | 方向 | 大小（预期） |
|---|---|---|
| ① heating 包含**所有反应**留下的能量：N-14 的 (n,p) 那 0.626 MeV、B-10 的 (n,α) 那 2.3 MeV 都在里面 | OpenMC 偏大 | 很大 —— 硼和氮的反应能量远大于反冲。**必须扣掉** |
| ② NJOY 算 KERMA 时假设**靶核静止**；你的是自由气体，热区上散射为负 | OpenMC 偏大（热区） | 热中子每次只带 ~0.03 eV，乘上碰撞数也远小于快中子反冲。预期 < 1% ⚠️ |
| ③ (n,γ) 的反冲核（²H 被 γ 反冲）在 KERMA 里 | OpenMC 偏大 | 每次几百 eV 到 1 keV 量级 ⚠️，小 |

**两个方案**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **甲** 只比「只有弹性的核素」 | OpenMC 的 heating 只选 H1、C12、O16（≤ 2 MeV 时它们除了弹性只有 (n,γ)，O-16 的 (n,α) 阈值 2.35 MeV 不开）；你那边 D_H 也只记这三种核素的反冲 | 两边干净地比同一个量；但**你的 run_slab 要加一个按核素分开的 D_H** —— 改代码 |
| **乙** 全部核素 heating 减掉已知反应能 | OpenMC：总 heating − (n,a)_B10 × Q_B − (n,p)_N14 × Q_N | 不改你的代码；但 N-14、B-10 还有别的反应（你筛道时看到的 800/801、600/601/700），扣不干净，偏差表里要列 |

## 8. 比的方法

每层每个量：

```
z_k = (你的_k − OpenMC_k) / sqrt(SE你的_k² + SE_OpenMC_k²)
```

两边是**独立的随机数**（不同程序、不同发生器），所以分母是两个 SE 平方和开根号 —— 和判据 2 一样。

**注意相邻层相关**（今天复查时你看到的：第 1 对 30 层 z 的平均是 +1.06，整条曲线一起往上浮）。所以：
- 单层 |z| > 4 → 几乎肯定是真的偏差
- 好几层同号 1–2 SE → **不一定**是偏差，可能是一次整体浮动。加大 N 再看（今天复查的同一个方法：真偏差随 √N 变大，噪声不会）

| 通量 | | | | | |
| D_B | | | | | |
| D_N | | | | | |
| (n,γ) | | | | | |

## 11. 自测题（明天读完自己答，答不出的开工时问）

1. 30 层、两个都正确的程序，期望大约有几层落在 1σ 外？几层落在 2σ 外？（提示：§1）
2. OpenMC 里材料用 `'ao'` 而不是 `'wo'`，氢的「份额」会从 0.102 变成多少的量级？通量会偏高还是偏低？
