## 第 2 段 · `find(E, e)`：二分法找格子

### 2.1 它返回什么

「e 落在第 k 格」的意思是 **E[k] ≤ e < E[k+1]**。返回的是**下标 k（位置）**，不是 E[k]（值）—— 🔴 你混过「`.index()` 返回位置 vs 值」，这里一样要分清。

用本文的表 `E = [0.37, 1.9, 4.6, 12.5, 31.0, 88.0]`（6 个点 → 5 格，k 只能是 0–4）：

| 格 k | 范围 |
|---|---|
| 0 | [0.37, 1.9) |
| 1 | [1.9, 4.6) |
| 2 | [4.6, 12.5) |
| 3 | [12.5, 31.0) |
| 4 | [31.0, 88.0] |

### 2.2 逐行

```python
def find(E,e):
    n=len(E)
```
n = 6（表的点数）。

```python
    if e>=E[n-1]:
            return n-2
    if e<=E[0]:
            return 0
```
**先把两头处理掉**：
- e 在最后一个点上或者更大 → 返回 **n − 2** = 4（最后一格）。为什么不是 n − 1：插值要用 E[k] 和 **E[k+1]** 两个点，k = n − 1 时 E[k+1] 就越界了
- e 在第一个点上或者更小 → 返回 0（第一格）

（这两行的缩进是 12 个空格，比别的多。Python 只要求同一块里缩进一致，所以能跑。原样抄。）

```python
    lo=0
    hi=n-1
```
🔴 **不变量**：整个循环里一直保持 **E[lo] < e < E[hi]**，也就是答案一定在 lo 和 hi 之间。开头 lo = 0、hi = 5，上面那两个 `if` 已经保证了 e 严格在 E[0] 和 E[5] 之间，所以不变量一开始就成立。

```python
    step=0
    while True:
        step+=1
        assert step < 100, "二分没有收敛：lo=%d hi=%d（区间没在变小）" % (lo, hi)
```
- `while True`：一直循环，靠里面的 `return` 跳出去
- `step` 数转了几圈。**这条 assert 抓什么**：如果哪里写错了，区间不再缩小，`while True` 会变成死循环，程序卡住不动也不报错。二分法 100 圈能处理 2¹⁰⁰ 个点的表，所以转满 100 圈一定是写错了。消息里打出 lo、hi，一看就知道卡在哪

```python
        mid=(hi-lo)//2+lo
```
- `//` 是**整除**（扔掉小数）：7 // 2 = 3
- mid = lo 和 hi 正中间那个下标。写成 `(hi-lo)//2+lo` 而不是 `(lo+hi)//2`，两者结果一样，这是白板⑤你写的形式

```python
        if e>E[mid]:
            lo=mid
        if e<E[mid]:
            hi=mid
        if e==E[mid]:
            return mid
```
- e 比中点大 → 答案在右半边 → lo 挪到 mid
- e 比中点小 → 答案在左半边 → hi 挪到 mid
- 正好等于中点 → e 就在第 mid 格的左端点上，直接返回

每一步都保持 E[lo] < e < E[hi]，区间缩小一半。

```python
        if hi-lo==1:
            return lo
```
lo 和 hi 挨着了 → E[lo] < e < E[lo+1] → 答案就是 lo。

### 2.3 算例：e = 7.3，一步一步

| 圈 | lo | hi | mid | E[mid] | 比较 | 之后 |
|---|---|---|---|---|---|---|
| 1 | 0 | 5 | (5−0)//2+0 = **2** | 4.6 | 7.3 > 4.6 | lo = 2 |
| 2 | 2 | 5 | (5−2)//2+2 = **3** | 12.5 | 7.3 < 12.5 | hi = 3 |
| — | 2 | 3 | | | hi − lo = 1 | **return 2** |

结果 k = 2，对照 2.1 的表：7.3 在 [4.6, 12.5) 里 ✅

## 第 3 段 · `interp_loglog(E_tab, S_tab, e)`：log-log 插值

### 3.1 公式从哪来

截面在双对数坐标里一小段一小段近似是直线。「双对数坐标里的直线」就是：

ln S = a + p · ln E

两边取 exp：**S = (常数) × E^p**，也就是幂函数。p 是这条直线在双对数图上的**斜率**。

过两个点 (E[k], S[k]) 和 (E[k+1], S[k+1])：

- 斜率 **p = ln(S[k+1]/S[k]) / ln(E[k+1]/E[k])** （纵向差 ÷ 横向差，只是差都取了 ln）
- 从左端点出发：**S(e) = S[k] × (e / E[k])^p**

检查一下：e = E[k] 时 (e/E[k])^p = 1，得到 S[k] ✅；e = E[k+1] 时，代进去得 S[k] × (S[k+1]/S[k]) = S[k+1] ✅。

这就是白板⑥你推的「幂形式」。

### 3.2 逐行

```python
def interp_loglog(E_tab, S_tab, e):
    k = int(np.searchsorted(E_tab, e, side="right")) - 1
```
定位 e 在第几格。`np.searchsorted(E_tab, e, side="right")` 返回「e 插进表里、放在相同值右边时的位置」，**减 1** 就是 E[k] ≤ e 的那个 k。
- 为什么不用你手写的 `find`：第 5 课判据 B 验过两者给出同一个下标，验过之后就换成 numpy 自带的快版本。手写 `find` 的价值是**面试能默写**
- 外面套 `int(...)`：`searchsorted` 返回的是 numpy 的整数类型，转成普通 Python 整数

```python
    k = min(max(k, 0), len(E_tab) - 2)
```
**夹住 k，不让它越界**，从里往外读：
- `max(k, 0)`：e 比表的第一个点还小时，searchsorted 返回 0，减 1 变成 −1 → 夹回 0
- `min(…, len−2)`：e 在最后一个点上或者更大时，k 会是 len − 1 → 夹回 len − 2（和 `find` 返回 n − 2 是同一个理由：要用到 k+1）

```python
    p = np.log(S_tab[k+1]/S_tab[k])/np.log(E_tab[k+1]/E_tab[k])
    return S_tab[k]*(e/E_tab[k])**p
```
3.1 的两个式子，原样。用 `np.log` 不用 `math.log`，是因为 `np.log` 也能吃 numpy 数组。

### 3.3 算例：e = 7.3，表用 `E = [0.37, 1.9, 4.6, 12.5, …]`、`S = [41.0, 18.2, 11.7, 7.1, …]`

```
k：      7.3 在 [4.6, 12.5) → k = 2
p：      ln(7.1/11.7) / ln(12.5/4.6) = ln(0.60684) / ln(2.71739)
       = −0.49948 / 0.99967 = −0.49965
结果：   11.7 × (7.3/4.6)^(−0.49965) = 11.7 × 1.58696^(−0.49965)
       = 11.7 × 0.79394 = 9.2891
```
p ≈ −0.5，就是 S ∝ E^(−1/2) = 1/√E。这张表是我照「1/v 截面」的样子编的，所以斜率接近 −1/2。

## 第 4 段 · `number_density(w, awr)`：数密度

### 4.1 先写单位，再写式子（9/8 救过你一次的那条）

| 量 | 单位 | 意思 |
|---|---|---|
| RHO | g/cm³ | 1 cm³ 组织有多少克 |
| w | 无量纲 | 其中这个核素占多少质量 |
| NA | 个/mol | 1 mol 有多少个原子 |
| M = awr × M_N | g/mol | 1 mol 这个核素有多少克 |

要凑出 **个/cm³**：

(g/cm³) × (无量纲) × (个/mol) ÷ (g/mol) = 个/cm³ ✅

所以 N = w × RHO × NA / M。

### 4.2 逐行

```python
def number_density(w, awr):
    M = awr * M_N
    return w*RHO*NA/M
```
- `awr` = atomic weight ratio，**以中子质量为单位**的核素质量，直接从 `.h5` 文件里读（`load_nuclide` 返回的第 4 个值）。乘上 M_N 才是 g/mol
- 🔴 第 8 课的 `build_tissue` 里，`dens = MASS_FRAC[name]*RHO*N_A/(awr*M_N)` 就是这同一个式子，只是写在了一行里。今天下午你核对 OpenMC 数密度用的「你的公式」也是它

### 4.3 算例：w = 0.708（软组织里 O 的份额），awr = 15.8575（O-16 的量级，本文随手取的）

```
M = 15.8575 × 1.00866491588     = 15.99490 g/mol
N = 0.708 × 1.06 × 6.02214076e23 / 15.99490
  = 0.75048 × 6.02214076e23 / 15.99490
  = 4.51950e23 / 15.99490       = 2.8256e22 个/cm³
```
换成 OpenMC 用的单位 atom/b·cm 要 × 1e-24：0.028256。这和第 5 课判据 F 那张表里 O16 那一行的量级一样。
