**先看记号**

| 记号 | 意思 |
|---|---|
| AP（anterior–posterior）照射 | 平行束从人体**正前方**照向后方 |
| benchmark（基准） | 拿来当「标准答案」的程序：这里是 CPU 单线程跑的 Geant4 |
| CPU serial program（CPU 串行程序） | 作者把**自己的 GPU 程序原样搬回 CPU**、一个线程跑 —— 物理模型、加速结构、截断能量都和 GPU 版相同 |
| acceleration ratio（加速比） | 基准用时 ÷ 自己程序用时 |
| dose conversion coefficient（剂量转换系数） | 器官吸收剂量 ÷ 粒子注量，单位 Gy·cm²（每 cm² 打一个粒子，器官吃多少剂量） |
| batch-based method（批次法） | 把 10⁸ 个粒子分成若干批，每批算一个结果，用**批与批之间的散布**估统计误差 |
| single-precision（单精度浮点） | 32 位浮点数，大约 7 位有效数字（你 Python 里的 float 是 64 位双精度，约 16 位） |
| thread divergence（线程发散） | GPU 上一组线程（32 个）**一起**执行同一条指令；有的粒子先跑完，它的线程只能干等组里最慢的那个 |
| 10⁷ / 10⁸ | PDF 文字里排成了「107」「108」，指 10⁷、10⁸ 个粒子 |

**题 1（加速比拆成两段：功劳算谁的）**

§2.3 末段和 §3.2：作者跑了**三个**程序 —— Geant4 基准、CPU 串行、GPU。总加速比（基准 ÷ GPU）是 **120 – 2700 倍**。

(a) 「基准 ÷ CPU 串行」量的是什么带来的加速？「CPU 串行 ÷ GPU」量的又是什么？（两个比值乘起来就是总加速比。）§3.2 说第一个比值只是**个位数**：这说明 120 – 2700 倍主要是谁的功劳？

(b) 你 M5 之后也要报一个「GPU 加速比」。你现在的程序是 Python 写的（10/31 计时：每秒约 5.6 万条历史，lesson03 那个最简单的板）。
  - 如果你写「我的 GPU 版比我的 Python 版快 1000 倍」，面试老师最可能追问哪一句？（提示：Python 本身比 C++ 慢多少数量级？这 1000 倍里有多少是「从 Python 换成编译语言」白送的？）
  - 照这篇文章的做法，你应该拿哪几个程序来比，才能把「换语言」「GPU 并行」两份功劳分开？

**题 2（误差和线程发散：结果里的两个「例外」）**

(a) §3.1：大多数情况 GPU 程序和基准的剂量差在 **5% 以内**、在**两倍统计误差以内**；唯一的例外是 **0.01 MeV 电子**照射**皮肤敏感层（50–100 μm 深）**。
  - 10 keV 电子在水（软组织）里能走多远？说个数量级（nm、μm 还是 mm）。和 50–100 μm 比一比，为什么这层皮肤吃到的剂量**特别小**？
  - 剂量特别小，为什么**相对**差会特别大？用你自己的规则 14（先查 R = SE / 均值，R > 0.2 的层不能拿去算 z）解释一句。
  - 他们用「批次法」估误差，你用的是「逐条历史的标准误 SE」+「30 个种子之间的散布」。你 10/31 发现过哪一种情况下逐层的 SE 会**低估**？（提示：多层合成一个数。）

(b) §3.2 后两段：**电子**的加速比比光子高，**低能**粒子的加速比比高能高。作者的解释是线程发散：同一组里粒子的输运时间越**接近**，干等的线程越少。
  - 把这个道理用到你的 BNCT 中子上：在你的水板里，一条中子历史可能撞两三次就漏出去，也可能从快群慢化到热能、再扩散几十上百次才被吸收。中子的「输运时间」各条之间差别大还是小？你预计中子 GPU 版的线程发散比他们的电子**更严重**还是更轻？
  - 你的程序里**哪个计数**记的是「这条历史撞了几次」？要看各条历史长短差多少，你会怎么用它（说做法，不用写代码）？
